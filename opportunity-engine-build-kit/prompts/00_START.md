# First coding session

Read START_HERE.md, AGENTS.md, the BUILD_SPEC.md v2 overlay, IMPLEMENTATION_PLAN.md and PROGRESS.md. Inspect the real repository and preserve existing changes. Run npm test before modifying the kit.

Use the selected architecture in docs/architecture/DECISIONS.md. Resolve reversible implementation choices with an ADR; do not invent package versions, credentials or permission. Create the actual scaffold and lockfile under M0. Keep the supplied reference checks meaningful.

Before UI implementation, read design/DESIGN_BRIEF.md, UI_SPEC.md and QA.md. Produce at least two different compositions of the same evidence-review task. Provisionally choose the best-supported direction and record why; the reference preview is not a template to copy. Show actual browser screenshots, including a blocked state and narrow screen. No generic dashboard, decorative AI treatment, fake metrics or unmodified kit composition.

Implement the first feasible M1 slice after M0. Include persistence, authentication boundaries, tenant isolation, safe capture, atomic budgets, review versioning and actual tests—not just screens. Use isolated fixtures for local work; expose unavailable live integrations honestly. Do not deploy, purchase, send outreach or modify customer systems without explicit scoped authorization.

Finish by updating PROGRESS.md with files changed, exact commands/results, rendered-screen critique, unverified/blocked work and next smallest complete task. Do not stop after writing another plan when safe local implementation is possible.
