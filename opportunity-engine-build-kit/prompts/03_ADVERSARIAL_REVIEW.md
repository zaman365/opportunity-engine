# Independent implementation and design review

Inspect actual code, contracts, tests and rendered screens. Do not trust completion claims in comments or a prior agent's summary. Run applicable tests and attempt the documented negative scenarios in the authorized local/staging environment.

Look for missing tenant constraints, fake integrations, fixture leakage, unsafe URL/subrequest handling, stale review publication, floating-point money, omitted parent budgets, duplicate side effects, cancellation releasing unknown costs, model-created evidence and unsupported sales claims. Verify auth with invalid/expired/wrong-audience identities; do not attack third-party systems.

Review design at 1440 and 390 px plus keyboard/zoom: task hierarchy, evidence readability, honest states, contrast, focus, mobile action reachability and original expression. Identify generic template composition, redundant containers, decorative numbers, dead buttons and invented progress. Distinguish actual user tests from heuristic observations.

Report findings by severity with file/line or screenshot evidence, reproduction and concrete fix. Fix authorized local defects, rerun tests and update PROGRESS.md. Never weaken a test or fabricate a screenshot to improve the report.
