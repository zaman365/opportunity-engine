# M2 · five more detectors and eligible offers

## Outcome

Expand supported diagnostics without lowering the evidence standard. Implement MF-ASSET-01, MF-DATA-01, PDP-CONTENT-01, PDP-VISUAL-01 and PDP-MOBILE-01 using detector specifications.

## Tasks

For each detector: typed input/output, platform/category prerequisites, required artifacts, precise assertions/abstention, known false positives, root-cause family, negative controls and evaluation owner. Introduce model provider only for content/visual roles after schema/evidence evaluation; no open-ended autonomous browser. Bind prompts/models/rubrics to versions. Do not infer missing information without inspecting disclosed modules/accordions and supporting pages.

Use offer catalog with draft disabled prices until approved. Match detector family, prerequisites, capacity and authorized scope. Unsupported work routes to diagnosis/manual quote. Implement priority factors from explicit rubrics; unknown fields remain null/interval. Never translate priority into purchase probability or publish a sales-loss estimate.

## UI

Show technical defect vs qualitative recommendation as different assessed sections, with evidence and limitations. Reviewer sees contrary evidence and required specialist review. Catalog change requires owner and new version; existing quotes remain immutable.

## Tests/gate

Held-out positive/negative/blocked examples per detector; category ambiguity; variant/tax/currency consistency; missing assets; prompt injection; invalid model evidence ID; rank unknowns; root-cause duplication; ineligible/prerequisite-missing offer; unapproved catalog price. Report sample counts and reviewer disagreement, not a blanket “90% accuracy.”
