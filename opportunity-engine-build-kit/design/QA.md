# Design review and release rubric

## Three-pass record

For each pass save actual screenshots, viewport, scenario, observations, changes made and remaining issues. A written critique without inspecting a rendered screen is not enough. Do not invent research participants or claim usability testing when only a heuristic review occurred.

### Pass 1 · composition

Can a reviewer understand the selected account, observed problem, evidence and next action without scanning a wall of cards? Does the artifact get enough room? Is hierarchy specific to this product? Compare at least two alternate compositions before locking the main direction.

### Pass 2 · task usability

Complete a case from queue to finding decision. Use keyboard only, long names, partial evidence, missing permission and a stale-version conflict. Preserve notes. Try at 1440, 1024, 768, 390 and 320 px, at 200% zoom and with reduced motion. Every essential action must remain reachable.

### Pass 3 · craft and distinctiveness

Inspect alignment, line length, numerals, optical spacing, truncation, artifact scaling, status semantics, error recovery and focus. Remove redundant boxes and headings. Hide the logo and ask what makes this an evidence-review product rather than any SaaS dashboard. Naming another company's design is not a rationale.

## Acceptance rubric · internal heuristic, not an objective quality measurement

Score 1–5 with evidence: task clarity, evidence readability, uncertainty honesty, accessibility, responsive continuity, distinctive composition, typography/craft, state completeness. No dimension below 4 for a visual freeze. Accessibility failures, misleading data and nonfunctional actions are hard blockers regardless of average score. Actual user testing can invalidate a high heuristic score.

## Specific rejection triggers

Default sidebar + four interchangeable KPI cards + decorative chart as the main screen; gradient hero in a daily work tool; raw UI-kit components without authored hierarchy; every row in a floating card; large empty areas forcing needless scrolling; neon badges competing with proof; icon-only mystery navigation; tiny low-contrast text; fake progress; fictional live results; mobile hidden behind a desktop warning; all secondary actions in an unexplained ellipsis menu.

## Required screenshot set

Queue populated and empty; selected evidence with clear supported claim; blocked scan; partial scan; review conflict; unavailable artifact; protected report; settings cost limit; narrow mobile and keyboard focus. The provided prototype covers an initial subset only; M1 application screenshots remain required.
